# Security Policy 🔒

## Supported Versions

| Version | Supported          |
|---------|--------------------|
| 0.1.x   | ✅ Active development |
| < 0.1   | ❌ Not supported   |

## Reporting a Vulnerability

If you discover a security vulnerability, **please do NOT open a public issue**.

Instead, contact the maintainer directly:

- WebSite: [sharzhukov.com](https://sharzhukov.com)
- GitHub: [@Sharzhukov](https://github.com/Sharzhukov)
- Email: [admin@sharzhukov.com](mailto:admin@sharzhukov.com)

Please include:

- A clear description of the vulnerability
- Steps to reproduce it
- The affected version
- Your OS and compiler
- Any potential fixes (if known)

## Response Time

We will acknowledge your report within **48 hours** and provide a timeline for a fix.

## Disclosure Policy

- Once the vulnerability is fixed, we will release a patch.
- We will credit the reporter (if you wish) in the release notes.

## Security Best Practices

- Always use the latest stable tagged release.
- The core has **no external dependencies** — the attack surface is limited
  to the standard library and the code itself.
- Do not commit secrets, tokens, or private keys.
